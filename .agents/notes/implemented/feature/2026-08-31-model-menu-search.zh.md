# Agent Note：composer 模型菜单的筛选框

Status: implemented

[English](2026-08-31-model-menu-search.md) | 中文

## 问题

提供方目录已经长到普通滚动列表难以承受：单个提供方可以公布数十个模型，而 composer 的模型菜单（ModelSelect 的 Model 面板）会列出每个分组的每一行，要找到某个具体模型只能滚动并通篇目检整个目录。

## 决策

Model 面板在按提供方分组的列表上方提供一个筛选输入框。查询按模型名称或 id 的大小写不敏感子串收窄行；被筛空的分组随之隐藏；没有任何匹配时显示筛选专属的空态文案（`empty.search`）——与目录空态（`empty.models`）区分开，后者仍表示目录本身一行都没有。Enter 选中第一个可见行；方向键落到菜单既有的根处理器上，把焦点移入筛选后的列表。每次打开菜单时查询重置，后续访问不会被陈旧筛选词藏住行。

筛选仅影响呈现：它读取的仍是未筛选列表渲染的同一份 `state.groups`，选择、分组与失败行均不受影响，`/model` popupSelect 入口也不变。

## 备选方案

**在共享的 popupSelect 原语里做搜索。** 作为另一项变更而拒绝：图中所示界面是 composer 菜单，而 `/model` 入口的选项列表归 command-ui 原语所有；为单个消费者 widening 该原语的契约并不由本次需求支撑。

**提供方感知或模糊匹配。** 拒绝：对名称和 id 做子串匹配已覆盖真实查找（记住的任一片段），而评分排序会引入没有用户需求证据的排序决策。

## 测试

一个渲染测试钉住：按 id 子串匹配（大写查询命中小写 id）、被筛空的分组连同标题消失、无匹配时的筛选空态文案，以及 Enter 经真实 `select` 路径选中第一个可见行。

## 影响

长提供方目录现在可以通过输入模型名称或 id 的片段来导航。代价是 ModelSelect 里三个本地化键和一小段派生列表计算，就放在它所筛选的列表旁边。
